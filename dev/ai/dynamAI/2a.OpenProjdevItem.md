## Filename: 2a.OpenProjdevItem.md
**Version:** 1.6

Project development data at current stage

## Developer confirmations required
This dynamAI requires developer confirmation at the following steps:
- After Step 1: confirm item number/URL before continuing
- After Step 2: confirm item details and subitems before proceeding
- After Step 3: confirm projdev.yaml update before proceeding
- After Step 4: confirm generated steps before proceeding to Do Steps workflow
DO NOT rely on one confirmation for multiple steps. Each confirmation is specific to that step only.

## Purpose
Open a GitHub project item to work on within the current feature branch.

## Prerequisites
(The following is tested for in the steps)
- Feature branch exists and is active in Git
- Correct feature is listed in projdev yaml
- Item number or URL provided
- Developer confirmation before opening item
- No current item listed in yaml (because previous item has been closed, or its a new feature)
- If active_item exists in projdev.yaml:
  - Check if requested item is a subtask of active_item:
    - If yes: Check for uncommitted files using `git status --porcelain`
      - If uncommitted files exist: WARN developer and suggest commit first
      - Do not proceed to open subitem until files are committed
    - If no: WARN that moving to another feature before completing current one is not supported
      - Ask developer to close current item first

## Steps

### Step 1: Get Item Info
**Input:** Item number or URL (optional — may have been given in request)
**Action:**
- [ ] If not provided, ask developer for item number or URL.
- [ ] URL is https://github.com/{owner}/{repo}/issues/{itemNum}
- [ ] Warn and stop if anything goes wrong. 
**Output:** Item number, item URL
**Discussion:** Confirm item title with developer before continuing.

### Step 2: Fetch Item Details from GitHub
**Data:**
- item number from input,
- owner, repo from projdev.yaml
**Action:**
- Use aiCode/itemState.md to verify issue state is "open"
- If state is "closed", warn developer and ask to confirm
- Use aiCode/itemDetails.md to fetch item details (title, state, labels, milestone: {number, title, due})
- Use aiCode/subItems.md to fetch subitems
- Parse item body and comments for checkbox steps (lines starting with "- [ ]" or "- [x]")
- List all checkbox steps found in description and comments
**Output:** Item details (title, status, body, labels, milestone), subitems list, checkbox steps list
**Discussion:** Report item details, subitems found, and checkbox steps. Wait for ok.

### Step 3: Update projdev.yaml
**Data:** Item details, subitems list
**Action:**
- If active_item exists and new item is a subitem of active_item:
  - Save current steps.md progress to parent_item.steps_progress in projdev.yaml
  - This preserves parent's step completion status when moving to child
- Update projdev.yaml active_item and parent_item (see projdevUpdate.md "On Open Projdev Item" section for detailed field assignments)
- If opening feature.item, verify subtasks already populated from startFeature (no re-fetch needed)
- If opening other item, subtasks already fetched in Step 2 using aiCode/subItems.md
- If returning to parent item (parent_item.steps_progress exists):
  - Restore steps.md from parent_item.steps_progress
  - Clear parent_item.steps_progress after restoration
**Output:** Updated projdev.yaml, restored steps.md if returning to parent
**Discussion:** Confirm projdev.yaml updated and steps restored if applicable. Wait for ok.

### Step 4: Generate Steps for Item
**Input:** Item details, subitems list
**Action:**
- Read item body to understand what needs to be done
- If subitems exist, ask developer which subitem to work on first, or if working on parent item
- Generate steps in steps.md based on item requirements
- Include subtasks as separate steps if working on parent item
**Output:** steps.md populated with item steps
**Discussion:** Review generated steps with developer. Wait for ok before proceeding to Do Steps workflow.

## Notes
- If item is already active in projdev.yaml, warn developer
- If item belongs to different feature, warn developer
- Subitems will be opened individually and recursively with this DynamAI. Of course only after developer's OK for each, and only after closing the previous one.
- A parent item will be closed when all subitems were closed.
- **When moving back from subitem to parent**: Check if parent still has open subitems using aiCode/subItemsClosed.md before proceeding
