## Two-Phase Close Approach
Similar to commitAndPush, closeItem uses two phases:

**Phase 1: Close the item in GitHub**
- Advance stage to "in review"
- Create and add closing comment
- Close the GitHub issue
- Push the close to GitHub

**Phase 2: Update metadata**
- Update projdev.yaml (move to completed_items, clear active_item)
- Update steps.md (clear completed steps, add last action note)
- Commit metadata changes
- Push metadata

**Reasoning for two phases:**
- Phase 1 commits the actual work (closing the item) to GitHub
- Phase 2 commits the tracking metadata (projdev.yaml, steps.md) which gets modified BY the close process itself
- This avoids the circular dependency where closing modifies metadata, but metadata needs to be committed before closing
- Mirrors the commitAndPush pattern for consistency
