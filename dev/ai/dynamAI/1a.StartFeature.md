Filename: 1a.StartFeature.dynai
Version: 0.90

## Purpose
Start a new Gitflow feature branch from the develop branch.

## General Instructions
- Before each step: announce dynai name, step number, and step name.
- On error: report dynai name, step number, and one-line explanation.
- Do not proceed past any discussion point without developer's explicit ok.

## Prerequisites
- Feature name (will be requested if not provided)
- Must be on develop branch with clean committed and pushed state
- Feature branch must not already exist locally or on remote
- Developer confirmation before creating branch

## Steps

### Step 1: Get Feature Name
**Input:** Feature name (optional — may have been given in request)
**Action:**
- If not provided, ask developer for feature name.
**Output:** Feature name
**Discussion:** Confirm feature name with developer before continuing.

### Step 2: Read projdev.yaml
**Input:** New feature name
**Action:**
- Read `dev/ai/projdev.yaml` for previous iteration and branch context.
- Warn developer if:
  - Previous feature branch was not closed (name differs from new)
  - Active item still open from previous iteration
**Output:** Previous iteration name, branch, and active item (if any)
**Discussion:** Inform developer of any warnings. Wait for ok.

### Step 3: Check Local State
**Input:** Feature name
**Action:**
- .1 Get current local branch:
  `git branch --show-current`
  - If already on `feature/<featurename>`: warn developer, skip to Step 6.
  - If on another feature branch: warn with that name, ask to close it
    (if yes: call `dev/ai/cmd/1b.EndFeature.dynai.md`) or ignore and continue.
  - If not on develop: warn and stop. Ask developer to switch to develop.
- .2 Check working tree is clean:
  `git status --short`
  - If not empty: warn developer. Do not continue until resolved.
- .3 Check everything is pushed:
  `git status -sb`
  - If "ahead" appears: warn developer. Do not continue until pushed.
**Output:** Local branch status, working tree status, push status.
**Discussion:** Report results. Wait for ok before continuing.

### Step 4: Check Remote
**Input:** Feature name, owner, repo from projdev.yaml
**Action:**
- Check if feature branch already exists on remote:
  `gh api repos/{project.owner}/{project.repo}/git/refs/heads/feature/<featurename>`
  - 404 = does not exist. Safe to create.
  - 200 = already exists. Warn developer and ask how to proceed.
**Output:** Remote branch status.
**Discussion:** Report result. Wait for ok.

### Step 5: Create or Move to Feature Branch
**Input:** Feature name, remote status from Step 4
**Action:**
- If remote exists and developer confirmed to use it:
  `git checkout feature/<featurename>`
  Verify: `git branch --show-current`
- If does not exist:
  `git checkout -b feature/<featurename>`
  Verify: `git branch --show-current`
**Output:**
- created: Branch `feature/<featurename>` created.
- existing: Moved to existing branch `feature/<featurename>`.
- error: `<step where it failed and what happened>`
**Discussion:** Confirm result with developer. Wait for ok.

### Step 6: Update projdev.yaml
**Input:** Feature name, branch name, owner, repo from projdev.yaml
**Action:**
- Update projdev.yaml:
  - `iteration.name` = feature name
  - `iteration.branch` = `feature/<featurename>`
  - `iteration.iteration_field_id` = fetch with:
    `gh project field-list {project.project_id} --owner {project.owner} --format json | cat`
    locate the Iteration field id in the result.
- If previous iteration differs from new:
  - Clear: head_item, parent_item, active_item, commits, completed_items.
**Output:**
- updated: projdev.yaml updated with new iteration.
- reset: projdev item fields cleared. No active item.
- kept: Active item `[#number](url) title` carried over (same iteration).
**Discussion:** None. Proceed to report completion to developer.
