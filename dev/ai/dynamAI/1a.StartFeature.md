# Pseudo:
Goal: Start a new Gitflow feature branch from develop branch

Inputs: feature name (optional), GitHub issue URL/number (optional)

Prerequisites:
- Must be on develop branch with clean committed and pushed state
- Feature branch must not already exist locally or on remote
- Developer confirmation before creating branch

1. Validation:
1.1. Verify feature name format (if provided)
1.2. Verify GitHub issue is suitable as feature item (if provided)
1.3. Verify issue state is "open" (if provided)
1.4. Verify on develop branch or handle appropriately
1.5. Verify working tree is clean
1.6. Verify everything is pushed
1.7. Verify feature branch does not exist on remote

  Steps:
    {Self listing}
    {Validation steps}
    {Action steps}
    {Result verification steps}

2.1. Get feature name and GitHub issue (if not provided)

### Step 1.1 Get feature name and GitHub issue
1.1.1 If feature name not provided, ask developer for feature name
1.1.2 If GitHub issue URL/number not provided, ask developer for it
1.1.3 If GitHub issue provided:
  - Parse to get: issue number, issue URL, issue title
  - Verify issue is suitable as feature item using aiCode/isFeatureItem.md
  - Verify issue state is "open" using aiCode/itemState.md
  - Parse item body and comments for checkbox steps
  - List all checkbox steps found
  - Update projdev.yaml with feature.item and active_item (see projdevUpdate.md "On Start Feature" subsection 1)
  - Fetch and cache project details (including statusFieldUID and stage option UIDs) using aiCode/projectDetails.md (see projdevUpdate.md "On Start Feature" subsection 3)
  - Advance workflow stage to "in progress" using aiCode/itemStage.md setter
On result:
- problem: Consult the developer
- no problem: Close step

### Step 1.2 Read projdev.yaml
1.2.1 Read `dev/ai/working/projdev.yaml` for previous feature and branch context
1.2.2 Warn developer if previous feature branch was not closed
1.2.3 Warn developer if active item still open from previous feature
On result:
- problem: Consult the developer
- no problem: Close step

### Step 1.3 Check local state
1.3.1 Get current local branch: `git branch --show-current`
1.3.2 Handle branch status:
  - If already on `feature/<featurename>`: warn developer, skip to Step 2.3
  - If on another feature branch: warn, ask whether to close it or ignore
  - If not on develop but not a feature branch: warn and stop
1.3.3 Check working tree is clean: `git status --short`
1.3.4 If uncommitted files exist:
  - If only steps.md and projdev.yaml are uncommitted:
    - Check if they reflect a recent completed commit (compare with projdev.yaml commits section)
    - If yes: Notify developer that metadata files are uncommitted but reflect recent commit
    - Consult developer: Should we add a step to commit metadata files only, then re-run dynamAI task?
    - Wait for developer's ok
    - If developer agrees: Add step to steps.md to commit metadata, stop dynamAI task
  - If other files are uncommitted: WARN developer and ask to resolve first
1.3.5 Check everything is pushed: `git status -sb`
On result:
- problem: Consult the developer
- no problem: Close step

### Step 1.4 Check remote
1.4.1 Check if feature branch exists on remote:
  `gh api repos/{project.owner}/{project.repo}/git/refs/heads/feature/<featurename>`
1.4.2 Handle result:
  - 404 = does not exist. Safe to create
  - 200 = already exists. Warn developer and ask how to proceed
On result:
- problem: Consult the developer
- no problem: Close step
