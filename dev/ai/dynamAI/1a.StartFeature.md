## Filename: 1a.StartFeature.md
**Version:** 1.0

Project development data at current stage

## Developer confirmations required
This dynamAI requires developer confirmation at the following steps:
- After Step 1: confirm feature name and GitHub issue before continuing
- After Step 2: confirm before proceeding to local state check
- After Step 3: confirm before proceeding to remote check
- After Step 4: confirm before proceeding to branch creation
- After Step 6 (branch creation): confirm before proceeding to projdev.yaml update
- After Step 6 (projdev.yaml update): confirm completion
DO NOT rely on one confirmation for multiple steps. Each confirmation is specific to that step only.

## Purpose
Start a new Gitflow feature branch from the develop branch.

## Prerequisites
- Feature name (will be requested if not provided)
- Must be on develop branch with clean committed and pushed state
- Feature branch must not already exist locally or on remote
- Developer confirmation before creating branch

## Steps

### Step 1: Get Feature Name and GitHub Issue
**Input:**
- Feature name (optional — may have been given in request as url)
- GitHub issue URL/number (optional — may have been given in request)
**Action:**
- If feature name not provided, ask developer for feature name.
- If GitHub issue URL/number not provided, ask developer for it.
- If GitHub issue provided:
  - Parse to get: issue number, issue URL, issue title
  - Verify issue is suitable as feature item using aiCode/isFeatureItem.md:
    - Checks: has feature name format (title starts with "feature/"), has no parent
    - If not valid, stop with error
  - Verify issue state is "open" using aiCode/itemState.md
    - If state is "closed", stop with error: "Issue is already closed"
  - Parse item body and comments for checkbox steps (lines starting with "- [ ]" or "- [x]")
  - List all checkbox steps found in description and comments
  - Update projdev.yaml immediately with this information as feature.item and active_item (see projdevUpdate.md "On Start Feature" section 1 for detailed field assignments)
  - Advance workflow stage to "in progress" using aiCode/itemStage.md setter
**Output:** Feature name, GitHub issue info (if provided), checkbox steps list
**Discussion:**
- Confirm feature name with developer before continuing.
- If GitHub issue provided, confirm it was recorded in projdev.yaml as active_item and workflow stage advanced.
- Report checkbox steps found.

### Step 2: Read projdev.yaml
**Input:** New feature name
**Action:**
- Read `dev/ai/projdev.yaml` for previous feature and branch context.
- Warn developer if:
  - Previous feature branch was not closed (name differs from new)
  - Active item still open from previous feature
**Output:** Previous feature name, branch, and active item (if any)
**Discussion:** Inform developer of any warnings. Wait for ok to proceed

### Step 3: Check Local State
**Input:** Feature name
**Action:**
- .1 Get current local branch:
  `git branch --show-current`
  - There can be 4 possible results: (1) Already on feature branch, (2) Still on other feature branch, (3) on develop branch (after previous feature closed), or (4) on some other non-feature branch (branch name doesn't start with "feature/")
  - Each result may still have uncommitted or unpushed code. 
    - If already on `feature/<featurename>`: warn developer, skip to Step 6 (update projdev.yaml)
    - If on another feature branch: warn with that name, ask whether to close it or ignore and continue.
      - If closing old feature requested, move to `dev/ai/dynamAI/1b.EndFeature.md`.
    - If not on develop but not a feature branch: warn and stop. Ask developer to switch to develop.
- .2 Check working tree is clean:
  `git status --short`
  - If not empty: warn developer. Do not continue until resolved.
- .3 Check everything is pushed:
  `git status -sb`
  - If "ahead" appears: warn developer. Do not continue until pushed.
**Output:** Local branch status, working tree status, push status.
**Discussion:** Report results in chat. record actions in steps. Wait for ok before continuing.

### Step 4: Check Remote
**Input:** Feature name, owner, repo from projdev.yaml
**Action:**
- Check if feature branch already exists on remote:
  `gh api repos/{project.owner}/{project.repo}/git/refs/heads/feature/<featurename>`
  - 404 = does not exist. Safe to create.
  - 200 = already exists. Warn developer and ask how to proceed.
**Output:** Remote branch status.
**Discussion:** Report result. Wait for ok.

### Step 6: Create or Move to Feature Branch
**Input:** Feature name, remote status from Step 4
**Action:**
- If remote exists and developer confirmed to use it:
  `git checkout feature/<featurename>`
  Verify: `git branch --show-current`
- If does not exist:
  `git checkout -b feature/<featurename>`
  Verify: `git branch --show-current`
**Output:**
- created: Branch `feature/<featurename>` created.
- existing: Moved to existing branch `feature/<featurename>`.
- error: `<step where it failed and what happened>`
**Discussion:** Confirm result with developer. Wait for ok.

### Step 6: Update projdev.yaml and steps.md
**Input:** Feature name, branch name, owner, repo from projdev.yaml
**Action:**
- Update projdev.yaml:
  - `feature.name` = feature name
  - `feature.branch` = `feature/<featurename>`
- If we just created a new feature:
  - If branch creation was initialized by a projdev item (recorded in step 1):
    - Leave feature.item, parent_item, active_item, and subtasks intact
  - If branch creation was NOT initialized by a projdev item:
    - Clear: feature.item, parent_item, active_item, commits, completed_items

**Output:**
- updated: projdev.yaml updated with new feature.
- preserved: projdev item fields preserved if initialized by projdev item.
- reset: projdev item fields cleared if not initialized by projdev item.
**Discussion:** Report completion to developer in AI chat
